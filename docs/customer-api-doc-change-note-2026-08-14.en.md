# Growatt Open API Documentation Change Notice

Release date: 2026-08-14

Applicable audience: platform customers, aggregators, VPP partners, and technical integration teams that have already integrated with, or are planning to integrate with, the Growatt Open API.

## 1. Overview

This update adds a site-level unique identifier to the device information query API, and documents the field values for the duration-and-power-percentage charge/discharge dispatch parameter.

The main updates in this release are:

- New `systemId` field in `getDeviceInfo`, identifying the site (plant) a device belongs to.
- Field value documentation for `duration`, `percentage`, and `type` in the `duration_and_power_charge_discharge` dispatch parameter.

## 2. Key Changes

### 2.1 New `systemId` field in `getDeviceInfo`

The device information query response now includes a `systemId` field identifying the site the device belongs to.

| Field | Type | Description |
| :--- | :--- | :--- |
| `systemId` | string | Globally unique site (plant) identifier generated by the Growatt cloud; identical across all devices under the same site and stable for the site's lifetime |

**Key points:**

- Each `systemId` uniquely identifies one site (plant).
- All devices under the same site return the same `systemId`.
- The `systemId` remains stable throughout the site's lifetime.

### 2.2 `duration_and_power_charge_discharge` field values

Field value documentation added for the duration-and-power-percentage charge/discharge dispatch parameter:

| Field | Type | Description |
| :--- | :--- | :--- |
| `duration` | int | Duration in minutes. `0` means unlimited; `1~1440` minutes controls by the set duration |
| `percentage` | int | Percentage of rated battery charge/discharge power, range `[-100,100]`; positive means charging and negative means discharging |
| `type` | string | Command type: `selfConsumptionCommand`, `chargeOnlySelfConsumptionCommand`, `chargeCommand`, or `dischargeCommand`; the first two charge/discharge at the maximum available power by default, in which case `percentage` is ignored |

## 3. Affected APIs and Documentation

- Updated: `POST /oauth2/getDeviceInfo` — response now includes the `systemId` field
- Updated: Global parameters — added `duration_and_power_charge_discharge` field value documentation

## 4. Impact on Customers

### 4.1 For new integrations

- When integrating `getDeviceInfo`, you can read `systemId` to identify the site a device belongs to.
- When setting `duration_and_power_charge_discharge`, pass parameters according to the field value documentation above.

### 4.2 For existing integrations

- No breaking changes. Existing API paths, request parameters, and response structures are unchanged.
- `getDeviceInfo` only gains an additive field; existing fields are unchanged. If your parsing logic strictly validates fields, allow the new field.

## 5. Recommended Customer Actions

1. Review the `getDeviceInfo` API and decide whether to read `systemId` in your integration.
2. When using `duration_and_power_charge_discharge`, set `duration`, `percentage`, and `type` according to the field value documentation.

## 6. Compatibility Notes

- API paths for existing endpoints are unchanged.
- The OAuth2 integration flow is unchanged.
- No existing fields are renamed or restructured; `systemId` is purely additive.
- This release contains no breaking changes and does not affect existing integrations.
