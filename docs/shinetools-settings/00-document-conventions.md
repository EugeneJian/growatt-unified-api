# 文档约定与整理方法

[返回总导航](./README.md)

## 目标

本专题需要同时解决三个问题：

1. 让人不打开飞书画板也能顺序阅读设置项。
2. 把“页面结构、设置语义、适用机型、寄存器提示”分开表达。
3. 为后续落入结构化数据或正式产品文档保留可追溯来源。

## 文档分层

| 层级 | 内容 | 作用 | 是否属于 SSOT |
|---|---|---|---|
| 原始来源 | 飞书 Docx 中的三个内嵌画板 | 原始视觉材料 | 否 |
| 导出来源 | 画板 RAW JSON | 保留节点、父子关系、坐标和样式 | 否 |
| 生成大纲 | `sources/*.md` | 只保留文字和父子层级，便于检索与差异分析 | 否 |
| 阅读文档 | `modules/*.md` | 解释模块、交互、差异和问题 | 否，属于评审层 |
| 未来设置项 SSOT | 待设计的 JSON/YAML 数据模型 | 经人工确认后承载结构化事实 | 是，当前尚未建立 |

标题、版面标记和无子节点的视觉根对象属于来源治理信息，由 M05 单独归档，不进入功能设置树。

## 证据标记

模块文档使用以下三类证据状态：

- **来源事实**：画板节点直接写出的名称、层级、可见性说明或标识。
- **分析**：根据信息架构或常见产品交互得出的解释，不等同于协议事实。
- **待确认**：当前材料不足以确定，需要产品、研发、协议或实机验证。

分析内容不得覆盖来源事实。发现来源冲突时，应同时保留各视图表达并登记问题。

## 单模块文档模板

每个模块至少包含：

1. 模块结论
2. 模块边界
3. 功能结构
4. 设置项清单
5. 交互与依赖分析
6. 机型或视图差异
7. 寄存器与标识提示
8. 待确认问题
9. 来源追踪

## 命名约定

- 页面和设置项名称保留来源英文，例如 `Quick Site Setup`、`Export Limitation Setting`。
- 中文用于解释语义，不擅自替换产品正式名称。
- `holdNN`、`inputN` 作为原始提示原样保留。
- 机型可见性规则使用“显示 / 隐藏 / 条件显示 / 待确认”四种状态。
- 节点中的“删除、确认、建议、开关按钮”等文字保留在 `source_text`，并分别转为生命周期、评审、适用性或 UI 候选字段。
- 来源写有“删除”时只标记为 `deprecated_candidate`；没有确认人、继任项和生效版本时，不标记为正式 `deprecated`。

## 一次一块的迭代规则

1. 从总导航选择一个未整理模块。
2. 在三个来源大纲中提取同名子树。
3. 做结构对比，区分公共结构和视图特有信息。
4. 编写模块阅读文档并登记所有待确认项。
5. 校验本地链接、来源覆盖和节点遗漏。
6. 更新总导航状态，再进入下一模块。
