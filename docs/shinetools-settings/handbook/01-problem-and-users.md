# 01 为什么能管设置难用，用户真正要完成什么？

[Handbook 导航](../product-handbook.md) · [下一页：参数如何分组](./02-parameter-grouping.md)

> **这一页只回答一个问题：用户进入能量管理设置时，真正想完成什么？**

## 一句话答案

用户想实现一种可验证的能源行为，例如零馈电、峰谷充放电或备电保留；他不想先理解分散的页面、机型差异和寄存器。

## 用户看到的不是参数

```mermaid
flowchart LR
    A[用户目标] --> B[需要多组参数]
    B --> C[页面与条件分散]
    C --> D[遗漏或冲突]
    D --> E[行为不符合预期]
    E --> F[反复修改与求助]
```

用户的自然语言通常是：

- “我要做零馈电。”
- “我要低谷充电、高峰放电。”
- “我要停电时至少保留 30%。”
- “为什么电池有电却不放电？”
- “为什么开启防逆流后仍然有馈电？”

产品的责任是把目标翻译成参数组合，而不是让用户自己完成翻译。

## 主要用户

| 用户 | 当前任务 | 最需要的帮助 |
|---|---|---|
| 现场投运工程师 | 一次完成新站能管配置 | 向导、依赖检查、推荐值、结果验证 |
| 售后 / 远程支持 | 解释为什么行为不符合预期 | 当前配置快照、冲突提示、最小修正集 |
| 产品 / 协议 / 固件 | 定义和验证参数 | 唯一设置模型、能力矩阵、版本关系 |

终端业主不是当前复杂工程参数页面的主要设计对象。若未来开放给终端用户，应通过目标模板重新设计。

## 核心 Jobs to Be Done

| Job | 成功结果 |
|---|---|
| 首次配置 | 必需参数一次完成，设备行为验证通过 |
| 切换策略 | 从当前模式安全切换到目标模式 |
| 调整电池边界 | 功率、SOC 和从网充电共同符合目标 |
| 配置防逆流 | 测量有效，实际馈电保持在目标范围 |
| 设置 TOU | 时段无冲突，并按计划进入正确状态 |
| 修正异常行为 | 找到阻止目标行为的配置并验证修正 |
| 复制配置 | 复用语义配置，同时处理设备差异 |

## 为什么当前结构让用户困难

| 复杂性 | 典型表现 | 产品问题 |
|---|---|---|
| 条件复杂 | 机型、固件、法规、拓扑决定是否适用 | 用户不知道入口为什么出现 |
| 依赖复杂 | 防逆流依赖 Meter / CT、目标和 Phase | 单独打开开关仍可能无效 |
| 模式复杂 | TOU、Backup、Peak Shaving 参数不同 | 所有字段平铺造成误解 |
| 来源重复 | Quick Setup、Quick Setting、EMS 重复 | 不知道哪里才是有效入口 |
| 验证缺失 | 页面只显示写入成功 | 无法证明能源目标达成 |

## 产品边界

这一产品域负责：

- EMS 策略、时段、出口限制、测量输入、电池边界和相关场景配置。
- 把上述设置组织成目标驱动的配置流程。
- 写入后的回读和能源行为验证。

这一产品域只引用：

- 设备身份、Country Regulation、安装拓扑和 Work Status。
- 安规、设备维护、诊断和专家寄存器工具。

## 本页形成的产品决策

1. 能管设置首页应从用户目标和当前状态开始。
2. 参数页面不能成为唯一入口；首次配置和问题修正需要任务流程。
3. 用户成功标准是能源行为验证通过，不是保存按钮返回成功。
4. 诊断问题超出能管配置范围时，应带着配置上下文转到 ShineTools 的诊断能力。
